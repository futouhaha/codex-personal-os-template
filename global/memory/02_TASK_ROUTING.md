# 任务路由

这个文件用于帮助 Codex 判断任务应该如何推进。

它不是要求 Codex 每次都机械判断“该不该进 Codex”。只有当任务边界不清、目标模糊、涉及工具选择、是否项目化、是否需要外部动作时，才读取本文件。

---

## 1. 核心原则

先判断：

1. 这个任务是否涉及真实文件、目录、代码、终端、工具或项目记忆。
2. 这个任务是否需要多步推进。
3. 这个任务是否需要持续迭代。
4. 这个任务是否只是早期讨论、脑暴、概念解释或轻量判断。
5. 如果不用 Codex，是否有更轻、更快的方式。

默认原则：

- 纯讨论、纯判断、纯概念解释，优先先在对话里想清楚。
- 涉及真实项目、文件、代码、工具、终端、自动化、沉淀，适合进入 Codex 执行。
- 长期项目、AI 产品原型、网页系统、小工具、知识库、workflow，适合项目化管理。
- 高风险操作不要直接执行，先说明风险和方案，等待确认。
- 明确、低风险、可回滚的小任务，可以在任务范围内主动推进。

---

## 2. 什么时候先讨论

以下情况，优先先讨论，不要急着执行：

- 用户只是想理解一个概念
- 用户只是在脑暴方向
- 需求还很模糊
- 用户还没有明确交付物
- 没有真实文件、目录、代码或项目上下文
- 只是想判断“这个事值不值得做”
- 只是想把想法说清楚
- 只是想比较几种方案
- 任务不需要跑命令、改文件、接工具或沉淀项目记忆

这种情况下，Codex 应该先给全局判断，帮 {{USER_NAME}} 把目标、边界、交付物说清楚，只问少量关键问题，不直接创建文件、写代码或安装工具。

---

## 3. 什么时候进入执行

以下情况，适合进入 Codex 执行：

- 需要读写真实文件
- 需要改代码
- 需要跑终端命令
- 需要检查项目目录
- 需要创建项目结构
- 需要开发 HTML / React / 前端原型
- 需要生成 Word / PPT / Excel / Markdown / HTML 文件
- 需要接入飞书 CLI、GitHub CLI、Playwright、部署工具等
- 需要调试 bug
- 需要跑测试
- 需要整理大量文件
- 需要把流程沉淀成项目记忆
- 需要持续迭代一个系统或产品原型

进入执行前，如果任务不够清楚，应先对齐目标、交付物、边界、完成标准和是否需要记忆沉淀。

---

## 4. 一次性任务、长期项目和特殊项目

不要把所有任务都项目化。

### 一次性任务

适合一次性处理的情况：

- 小修改
- 临时生成一个文件
- 临时整理一段内容
- 临时跑一个命令
- 一次性检查报错
- 不需要长期记忆
- 不会持续迭代

这种情况可以在当前 Codex 对话中直接做，但仍需遵守确认规则。

### 长期项目

适合项目化的情况：

- 会持续迭代
- 会产生多个文件
- 会反复修改
- 需要项目记忆
- 需要长期上下文
- 需要多次任务衔接
- 是 AI 产品原型、小工具、网页系统、知识库、内容系统、Copilot、workflow
- 未来可能需要部署、浏览器、CLI、自动化、RAG、飞书或其他工具

这种情况应启动 Project Onboarding。读取：

`03_PROJECT_ONBOARDING_PROTOCOL.md`

### 特殊项目

如果当前项目已经有成熟的项目级 `AGENTS.md`、特殊记忆结构、特殊索引文件或特殊调用链，不要强行套用默认项目模板。

处理方式：

1. 先读取当前项目 `AGENTS.md`。
2. 再按项目规则读取它指定的记忆或索引文件。
3. 如果项目规则和默认模板不同，以项目规则为准。
4. 如果项目规则和全局安全红线冲突，以全局安全红线为准。
5. 不确定时，向 {{USER_NAME}} 说明冲突点并等待确认。

---

## 5. Project Onboarding 触发条件

当用户表达以下意图时，优先判断是否需要 Project Onboarding：

- “我想做一个项目”
- “我想做一个系统”
- “我想做一个 AI 产品原型”
- “我想做一个小工具”
- “我想做一个网页”
- “我想做一个 workflow”
- “我想把这个长期沉淀下来”
- “我以后还会继续迭代”
- “这个东西可能会接飞书、浏览器、知识库、RAG、自动化”

如果判断为长期项目，不要直接开始实现。先读取 `03_PROJECT_ONBOARDING_PROTOCOL.md`，通过问答对齐项目目标、交付物、使用者、边界、工具、风险和记忆结构，再提出项目 `AGENTS.md` 和项目记忆结构草案。

如果用户明确说“先别项目化”，可以先按一次性任务处理，但高风险动作仍需确认。

---

## 6. 任务复杂度等级

### Level 1：轻量问答

只是解释、判断、讨论，不需要文件、命令或工具。直接回答，不进入项目。

### Level 2：轻量执行

有明确小任务，影响范围小，可回滚，不涉及外部系统，不需要长期记忆。可以在当前对话执行，高风险操作仍需确认。

### Level 3：项目任务

需要读写多个文件、持续迭代、记录进度，有项目目标和交付物。应读取项目 `AGENTS.md`，按项目记忆路由推进，任务结束后建议复盘和沉淀。

### Level 4：复杂系统任务

多模块、多工具、多阶段，可能涉及外部平台、浏览器、部署、数据流、RAG、Copilot、自动化。必须先给全局方案、阶段拆解、验收标准、风险边界和状态锚点，不要黑箱执行。

---

## 7. 工具路由

### Web Search

适合查公开资料、官方文档、新闻、工具版本、最新能力和限制。不适合操作网页、读取登录态页面或验证本地 UI。

### In-app Browser

适合看本地网页、预览 HTML、检查无需登录的公开页面、调试 UI、截图验证。不适合登录流程、验证码、账号安全和高敏感页面。

### Chrome extension

适合必须使用真实 Chrome 登录态的网页。使用前必须先问 {{USER_NAME}}。遇到登录、密码、验证码、支付、私信、账号安全、token 页面，必须停止。

### Computer Use

适合必须操作桌面 App 或真实屏幕状态的任务。默认不使用，使用前必须先问 {{USER_NAME}}。

### CLI / API

适合飞书 CLI、GitHub CLI、部署 CLI、数据处理、文件生成和自动化流程。能用 CLI/API，就不要优先用网页手动操作。安装或配置前必须确认。

## 8. Skill 和 subagent

不要一开始就把所有流程做成 Skill。只有当流程重复、稳定、输入输出清楚、跨项目复用时，才建议做成 Skill。

不要默认使用 subagent。只有任务明显可并行、子任务边界清楚、额外成本值得、用户确认时，才建议使用。

详细规则见：

`07_SKILL_STRATEGY.md`

---

## 9. 什么时候必须停下来问

以下情况应停下来问用户：

- 目标或交付物不清楚
- 多种路线取舍明显
- 需要安装工具
- 需要修改项目结构
- 需要写入记忆
- 需要修改 `AGENTS.md`
- 需要访问登录态网页
- 需要使用 Chrome extension 或 Computer Use
- 需要对外发送或发布
- 需要部署、付费、修改权限或安全设置
- 任务可能影响账号、安全、权限或隐私
- Codex 不确定用户真实意图

提问时不要问一大串。只问当前阶段最关键的问题，并说明为什么要问。

---

## 10. 默认推进流程

当任务不确定如何推进时：

1. 判断任务类型。
2. 判断是否一次性任务、长期项目、特殊项目或复杂系统任务。
3. 判断是否需要先讨论。
4. 判断是否需要 Project Onboarding。
5. 判断是否需要读取项目 `AGENTS.md` 或项目记忆。
6. 判断是否需要工具。
7. 判断是否有风险。
8. 给出 1 到 3 个可选路径。
9. 推荐一个路径。
10. 等用户确认高风险动作。
11. 再执行。

不要跳过目标对齐直接做结构性改动。
