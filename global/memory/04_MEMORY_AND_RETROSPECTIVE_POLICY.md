# 记忆和复盘规则

这个文件用于指导 Codex 在任务结束后，如何帮助 {{USER_NAME}} 复盘、分类、沉淀经验。

它的目标不是“什么都记”，而是识别真正会影响后续协作效率的内容，避免重复踩坑，让项目经验能被下次读取，让全局偏好逐步稳定，让重复流程未来可以升级为 Skill。

写入任何记忆前，必须先给 {{USER_NAME}} 建议，并等待确认。

---

## 1. 核心原则

记忆的目标不是保存聊天全文，而是保存未来会复用的信息。

优先记录：

- 会反复影响协作方式的偏好
- 项目未来还会用到的事实
- 已确认的重要决策
- 已踩过、下次要避免的坑
- 工具、环境、依赖、路径、命令等可复用信息
- 可复用 prompt
- 可能未来做成 Skill 的流程

不要记录原始聊天全文、一次性闲聊、很快会过期的临时想法、没有复用价值的执行碎片、未确认的猜测或敏感信息。

---

## 2. 什么时候建议复盘

重要任务结束后，Codex 应主动问 {{USER_NAME}} 是否需要复盘。

适合复盘的情况：

- 完成了一个阶段性任务
- 创建或修改了项目结构
- 解决了 bug 或环境问题
- 做了重要技术选择
- 安装或配置了工具
- 产生了项目进展
- 发现了 {{USER_NAME}} 的稳定偏好
- 出现了卡点、误解、返工
- 任务涉及浏览器、飞书、部署、外部工具
- 任务可能未来会重复

不需要复盘的情况：

- 很小的一次性问答
- 临时解释概念
- 没有产生任何文件、决策、经验或可复用结论
- {{USER_NAME}} 明确说不需要

默认问法：

```text
这次任务已经完成。要不要我帮你做一次简短复盘，看看哪些内容值得沉淀到全局记忆、项目记忆、AGENTS.md 或未来 Skill？
```

---

## 3. 复盘输出格式

复盘时，先输出建议，不要直接写入。

```text
## 任务复盘建议

### 1. 这次完成了什么
...

### 2. 这次有哪些值得沉淀
...

### 3. 建议写入哪里
- 全局 AGENTS.md：
- 全局记忆：
- 项目 AGENTS.md：
- 项目记忆：
- 未来 Skill：
- 不建议记录：

### 4. 为什么值得记
...

### 5. 是否存在敏感信息风险
...

### 6. 需要你确认的写入动作
...
```

如果没有值得沉淀的内容，应明确说：

```text
这次任务主要是一次性操作，没有明显需要写入长期记忆的内容。
```

---

## 4. 写入建议必须具体

提出记忆写入建议时，不能只说“写入项目记忆”或“写入全局记忆”。

必须尽量具体到：

1. 目标文件
2. 目标 section
3. 写入方式：新增、追加、替换、合并、整理
4. 建议内容草案
5. 为什么放这里
6. 是否需要同步更新其他文件
7. 是否需要 {{USER_NAME}} 确认

如果建议修改 `AGENTS.md`，必须说明具体 section，不能要求整体重写。

---

## 5. 项目 AGENTS.md 和特殊记忆结构

本文件只提供全局通用的记忆分类原则。

当任务发生在某个项目中时，必须优先检查该项目是否存在：

`<project>/AGENTS.md`

如果存在项目 `AGENTS.md`，项目记忆的具体读取和写入规则，应以项目 `AGENTS.md` 为准。

如果项目有特殊记忆结构，应按该项目自己的索引、路由和写入规则执行，不强行套用默认 `docs/codex/00–05`。

默认优先级：

1. 用户当前明确指令
2. 全局安全红线和必须确认规则
3. 项目 `AGENTS.md`
4. 项目记忆路由或特殊记忆结构
5. 全局 `~/.codex/AGENTS.md`
6. 本文件的通用分类规则
7. 其他全局记忆文件

如果项目还没有 `AGENTS.md` 或项目记忆区，但任务明显是长期项目，应建议先执行 Project Onboarding，而不是随意写项目记忆。

## 6. 记忆分类

### 全局偏好

记录 {{USER_NAME}} 的长期协作偏好。默认位置：`01_WORKING_STYLE.md`。如果是必须遵守的硬红线，建议升级到 `~/.codex/AGENTS.md`。

### 全局方法

记录跨项目复用的方法论。默认位置包括 `02_TASK_ROUTING.md`、`03_PROJECT_ONBOARDING_PROTOCOL.md`、`04_MEMORY_AND_RETROSPECTIVE_POLICY.md`、`05_BROWSER_AND_SECURITY_POLICY.md`、`07_SKILL_STRATEGY.md`。

### 项目事实

只属于当前项目的事实，例如项目目标、当前阶段、交付物、目录结构、项目边界、当前下一步、项目中特定工具选择。默认写入项目当前状态或工具文件。

### 项目进展

记录项目推进情况，例如完成内容、阶段变化、修改文件、下一步、待确认事项。默认写入项目任务日志；如果影响当前状态，也更新当前状态文件。

### 决策

记录已经确认的重要选择，例如技术路线、项目边界、是否部署、是否接真实 API、是否使用 mock data、是否引入某个依赖。默认写入项目决策文件。

### 经验

记录踩坑、错误、反复卡点和经验。默认写入项目经验文件。如果多个项目反复出现同类经验，可以建议升级到 `08_CROSS_PROJECT_LEARNINGS.md`。

### 工具和环境

记录工具、依赖、安装、环境和配置经验。项目相关写入项目工具文件；跨项目规则写入 `06_TOOLING_AND_INSTALL_POLICY.md`。

### Prompt 模板

记录已经验证好用、未来会复用的 prompt 或任务模板。跨项目写入 `09_REUSABLE_PROMPTS.md`，项目专用写入项目 prompt library。

### Skill 候选

记录未来可能做成 Skill 的重复流程。先记录到 `07_SKILL_STRATEGY.md` 或 `08_CROSS_PROJECT_LEARNINGS.md`，不要立刻创建 Skill。

### 不应记忆

不要记录一次性闲聊、临时情绪、无复用价值碎片、未确认猜测、原始聊天全文、密码、验证码、2FA、token、API key、密钥、支付信息、私信、私密聊天、敏感账号信息或任何可能暴露隐私和安全的信息。

## 8. 升级规则

### 升级到全局 AGENTS.md

只有满足以下条件，才建议升级到 `~/.codex/AGENTS.md`：

- 影响所有项目
- 是必须遵守的硬规则
- 不遵守可能造成明显风险
- 已经多次验证
- {{USER_NAME}} 明确确认

不要把大量细节写进 `AGENTS.md`。

### 从项目记忆升级到全局记忆

当某个项目经验在多个项目中重复出现、代表 {{USER_NAME}} 长期偏好、对未来项目有复用价值、不含敏感信息时，可以建议升级到全局记忆。

升级时不要直接搬运项目原文。应提炼成通用经验，去掉项目私有细节。

### 创建或更新 Skill

当流程重复出现 3 次以上、步骤稳定、输入输出清楚、未来跨项目复用、普通 prompt 已显得重复，并且 {{USER_NAME}} 确认时，可以建议做成 Skill。

## 9. 项目复盘

项目任务结束后，复盘重点是当前项目状态、下一步、新决策、新经验、工具变化、风险限制、是否需要扩展项目记忆结构、是否需要升级为跨项目经验。

项目复盘建议格式：

```text
## 项目记忆更新建议

### 建议更新 `01_CURRENT_STATE.md`
原因：
建议内容：

### 建议更新 `02_TASK_LOG.md`
原因：
建议内容：

### 建议更新 `03_DECISIONS.md`
原因：
建议内容：

### 建议更新 `04_LEARNINGS.md`
原因：
建议内容：

### 建议更新 `05_TOOLING.md`
原因：
建议内容：

### 是否建议新增项目记忆文件
...

### 需要 {{USER_NAME}} 确认的写入动作
...
```

如果项目有特殊记忆结构，应按项目自己的文件名和 section 输出建议。

---

## 10. 全局复盘

全局复盘适合在多个项目出现同类问题、{{USER_NAME}} 长期偏好变清楚、某个规则被多次验证、某个工具策略跨项目适用、某个 prompt 跨项目好用、某个流程值得做成 Skill、当前全局记忆结构出现重复或冲突时进行。

全局复盘建议应说明建议更新的文件、建议新增或修改内容、为什么这是全局记忆、是否应升级到 `AGENTS.md`、是否有过度泛化风险、是否有敏感信息风险，以及需要 {{USER_NAME}} 确认的写入动作。

---

## 11. 复盘质量标准

好的复盘应该简短但有结构，区分事实、决策、经验、偏好，不把聊天全文塞进去，不把项目事实写进全局，不把全局偏好藏在项目里，能帮助下次更快、更稳，能避免重复踩坑。

不好的复盘只是流水账、只说“任务完成”、记录太多无关细节、没有下一步、没有可复用价值、把未确认猜测当成事实、把所有内容都写进一个文件，或写入前没有请 {{USER_NAME}} 确认。

---

## 12. 清理和合并

当记忆文件出现内容重复、规则冲突、项目事实混入全局、全局偏好散落在项目记忆、文件太长但没有索引、任务日志变成聊天转录、经验过期、流程应升级为 Skill、红线应升级到 `AGENTS.md` 时，应建议清理。

清理前必须先给整理方案，等待 {{USER_NAME}} 确认后再修改。

---

## 13. 更新规则

更新本文件前，必须先向 {{USER_NAME}} 提出建议，说明当前复盘或记忆规则哪里不够好、要改什么、为什么有长期价值、是否会让流程变重，以及应该改本文件、`AGENTS.md`、项目记忆还是 Skill。
