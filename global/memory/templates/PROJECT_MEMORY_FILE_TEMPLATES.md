# 项目记忆文件模板

这个文件用于生成具体项目的项目记忆文件初始内容。

它不是某个项目的实际记忆内容。每个长期项目都应该先完成 Project Onboarding，再根据项目问答结果生成项目专属版本。

生成项目记忆文件时，不要原样保留无意义占位符。如果某项暂时未知，可以写“待确认”或“暂无记录”。

---

## 1. 默认项目记忆文件

长期项目默认生成：

```text
docs/codex/
  00_INDEX.md
  01_CURRENT_STATE.md
  02_TASK_LOG.md
  03_DECISIONS.md
  04_LEARNINGS.md
  05_TOOLING.md
```

这 6 个文件是项目记忆的默认长期闭环。

---

## 2. 可选项目记忆文件

当项目复杂度上升时，可以按需新增：

```text
docs/codex/
  06_BROWSER_POLICY.md
  07_PROMPT_LIBRARY.md
  08_DATA_SOURCES.md
  09_DEPLOYMENT.md
```

新增前必须先向 {{USER_NAME}} 说明原因，并等待确认。

## 3. 模板：`docs/codex/00_INDEX.md`

````md
# 项目记忆索引

这个目录保存本项目的 Codex 协作记忆。

项目记忆目录：

`docs/codex/`

项目 `AGENTS.md` 负责说明什么时候读取这些记忆文件。本目录负责保存项目状态、进展、决策、经验和工具记录。

不要把原始聊天全文写进项目记忆。不要把账号、密码、验证码、token、API key、密钥、支付信息、私信、敏感数据写进任何项目记忆。

---

## 1. 项目记忆文件

### `01_CURRENT_STATE.md`

项目当前状态。

读取场景：

- 开始重要任务前
- 项目中断后重新开始
- 需要知道当前阶段、下一步、待确认问题
- 需要确认项目当前阶段目标或近期目标

这个文件是项目当前状态的主要来源。

### `02_TASK_LOG.md`

项目任务日志。

读取场景：

- 需要查看最近做了什么
- 需要回顾任务结果
- 需要做阶段交接
- 需要判断项目进展

不要把聊天全文写入任务日志。

### `03_DECISIONS.md`

项目决策记录。

读取场景：

- 涉及历史选择
- 涉及方案取舍
- 涉及技术路线
- 涉及项目边界
- 需要理解为什么之前这么决定

只记录已经确认的重要决策。

### `04_LEARNINGS.md`

项目经验和踩坑记录。

读取场景：

- 遇到 bug
- 遇到工具失败
- 遇到环境问题
- 遇到重复卡点
- 需要避免过去的错误

经验应写成“下次遇到类似情况应该怎么做”。

### `05_TOOLING.md`

项目工具和环境记录。

读取场景：

- 涉及依赖
- 涉及 CLI
- 涉及飞书、GitHub、Playwright
- 涉及部署、文件生成、环境变量
- 遇到 `command not found`、PATH、权限或包管理器问题

不要记录真实 token、密钥、密码或验证码。

---

## 2. 可选文件

以下文件按需创建，不是默认必建。

- `06_BROWSER_POLICY.md`：项目频繁涉及浏览器、Chrome extension、Computer Use、Playwright、登录态网页时创建。
- `07_PROMPT_LIBRARY.md`：项目出现多个可复用 prompt、任务模板、生成模板时创建。
- `08_DATA_SOURCES.md`：项目涉及多个资料源、数据源、PDF、表格、网页链接、知识库或 RAG 时创建。
- `09_DEPLOYMENT.md`：项目进入部署、上线、环境变量、域名、版本发布阶段时创建。

---

## 3. 更新规则

更新项目记忆前，必须先提出更新建议。

建议应具体到目标文件、目标 section、写入方式、建议内容草案、为什么值得记、是否有敏感信息风险。

等待 {{USER_NAME}} 确认后，再写入。

---

## 4. 清理规则

当项目记忆出现当前状态过期、任务日志过长、决策中混入未确认想法、经验重复、工具记录过期、项目经验适合升级为全局经验、扩展文件长期没有内容、项目记忆结构已经不适合当前项目时，应建议整理。

清理前必须先给整理方案，等待 {{USER_NAME}} 确认后再修改。
````
