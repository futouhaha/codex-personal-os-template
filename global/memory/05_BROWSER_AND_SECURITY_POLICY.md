# 浏览器和安全策略

这个文件用于指导 Codex 如何选择和使用 Web Search、In-app Browser、Chrome extension、Computer Use、Playwright，以及如何处理登录态网页和敏感信息。

核心原则：

- 能不用浏览器，就不用浏览器。
- 能用 Web Search 查公开信息，就不要打开网页登录态。
- 能用 In-app Browser 看本地页面，就不要用真实 Chrome。
- 能用 CLI / API，就不要优先手动操作网页。
- 涉及账号、密码、验证码、支付、私信、token、密钥时，必须停下来。
- 使用 Chrome extension 或 Computer Use 前，必须先问 {{USER_NAME}}。

---

## 1. 浏览器能力分级

### Web Search

用于查公开信息，适合官方文档、新闻、当前能力、工具版本、API 文档、产品介绍、公开网页内容和不需要登录的信息。

不适合操作网页、点击按钮、填表、读取登录态页面、验证本地 UI 或处理需要视觉判断的页面状态。

### In-app Browser

Codex 内置浏览器，用于看渲染后的网页。

适合本地开发服务器、HTML 文件预览、不需要登录的公开页面、UI 视觉检查、前端 bug 复现和页面修复后的验证。

不适合登录流程、登录态页面、普通 Chrome profile、cookies、浏览器扩展、已有 Chrome 标签页、密码、验证码、2FA、支付、私信、账号安全页面。

### Browser Use

让 Codex 操作 In-app Browser。

适合打开本地页面、点击页面元素、输入测试文本、检查渲染状态、截图、验证 UI 修复、运行只读页面检查脚本和下载页面资产。

不用于登录、绕过风控、处理验证码、操作高敏感页面或批量访问受限网站。

### Chrome extension

让 Codex 使用真实 Chrome 登录态。只在确实需要登录状态时使用。

适合 {{USER_NAME}} 已经手动登录好的网页、需要少量读取整理的登录态普通页面，以及无法通过 API / CLI 完成的网页任务。

使用前必须先问 {{USER_NAME}}。

不用于登录过程、密码输入、验证码、2FA、扫码登录、支付、私信、账号安全设置、密码管理器、token / API key / 密钥页面或高风险批量操作。

### Computer Use

让 Codex 操作 Mac 图形界面或桌面 App。这是高权限能力，默认不使用。

适合必须操作桌面 App、必须跨多个 App、CLI/API/浏览器插件都无法完成、需要查看真实屏幕状态的任务。

使用前必须先问 {{USER_NAME}}。使用时任务必须很窄，只操作明确 App 和明确流程，不碰敏感窗口。发现窗口不对，立即停止。

### Playwright

用代码控制浏览器，适合可重复运行的网页测试。

适合自己项目的前端自动化测试、本地网页功能验证、回归测试、截图测试、重复流程验证和 CI 自动检查。

不适合绕过验证码、绕过风控、批量抓取受限网站、自动登录第三方网站或操作违反网站规则的页面。

Playwright 默认按项目安装，不默认全局安装。安装前必须先问 {{USER_NAME}}。

## 2. 默认选择顺序

```text
1. Web Search
2. CLI / API
3. In-app Browser / Browser Use
4. Chrome extension
5. Computer Use
6. Playwright
```

不要一上来就使用高权限工具。

---

## 3. 公开信息任务

查资料、查新闻、查官方能力、查产品说明时，默认使用 Web Search。

如果 Web Search 足够，不要再打开 Browser。如果网页需要动态渲染、内容无法直接获取、或需要视觉判断，再考虑 In-app Browser。

---

## 4. 本地网页任务

本地网页、HTML、React、Vite、前端原型任务，优先使用 In-app Browser 或 Browser Use。

使用前建议确认本地服务器是否已启动、目标 URL、目标页面状态、只验证哪个具体问题、是否需要截图、是否需要修改代码后再次验证。

不要让浏览器任务无限扩散。浏览器任务应有明确页面、明确动作、明确验证标准。

---

## 5. 登录态网页任务

登录态网页必须更谨慎。

默认策略：

- 使用前必须先问 {{USER_NAME}}。
- 优先让 {{USER_NAME}} 自己在 Chrome 中登录好。
- Codex 只在登录完成后处理普通页面。
- 遇到登录、验证码、密码、支付、私信、账号安全页面时，必须停止。
- 不要读取、总结、截图或保存敏感页面内容。

推荐流程：

```text
1. Codex 判断任务确实需要登录态网页。
2. Codex 向 {{USER_NAME}} 说明为什么需要 Chrome extension。
3. {{USER_NAME}} 确认。
4. {{USER_NAME}} 自己登录好，并离开敏感登录页面。
5. Codex 只处理已登录后的普通目标页面。
6. 如果再次遇到登录/验证码/密码/安全页面，Codex 停止并让 {{USER_NAME}} 接管。
```

不要让 Codex 参与输入账号密码、验证码或 2FA。

## 6. 永远不要触碰的页面

以下页面或内容永远不要主动查看、操作、截图、总结、保存：

- 密码管理器
- Chrome 密码页面
- 账号安全设置
- 支付页面
- 银行、交易、付款页面
- 私信或私密聊天
- 验证码
- 2FA
- 短信码
- 邮箱验证码
- 二维码登录确认
- token
- API key
- 密钥
- 恢复码
- 隐私设置
- 账号权限管理
- 敏感后台数据
- 任何 {{USER_NAME}} 明确说不要看的页面

如果误入，立即停止。不要尝试记住、复述、保存这些页面的任何内容。

---

## 7. Chrome profile 安全建议

建议长期使用专门的 Chrome profile 给 Codex 相关任务。

推荐原则：

- 不用个人主力 Chrome profile 做高风险任务。
- Codex profile 中只登录必要网站。
- 不在 Codex profile 中同步个人密码。
- 不在 Codex profile 中安装密码管理器扩展。
- 不打开密码管理器、账号安全、支付、私信页面。
- 不使用 Always allow 处理高风险网站。

如果网站涉及高敏感个人账号，默认不要让 Codex 操作。

---

## 8. 网站风险分级

低风险：

- 本地 localhost
- 自己项目的开发页面
- 无需登录的公开文档
- 公开官网
- 公开资料页

中风险：

- 需要登录但只读的工作页面
- 飞书文档
- Notion
- Gmail 搜索结果
- 内部工具的普通页面

高风险：

- 支付
- 账号安全
- 密码
- 私信
- 评论发布
- 发帖
- 批量发送
- 删除数据
- 修改权限
- 提交表单
- 订单、交易、客户数据

高风险网站或页面不要 Always allow。中风险网站也应优先只允许当前 chat。

## 10. 反爬和访问限制规则

不要尝试绕过验证码、反爬、风控、频率限制、网站访问限制、登录限制、付费墙或网站条款。

如果网站阻止自动化访问，应停止并说明限制是什么、可能原因、是否有官方 API/导出/CLI/手动下载/授权方式，以及是否应改用更合规的路径。

---

## 11. 截图和页面上下文规则

截图和页面内容可能进入任务上下文。

因此：

- 不截图敏感页面
- 不截图密码、验证码、支付、私信、token 页面
- 不让敏感信息出现在浏览器可见区域
- 不把敏感截图保存到项目目录
- 不把敏感页面内容写进记忆或日志

凡是 {{USER_NAME}} 不愿意出现在截图里的内容，都不要让 Codex 看到。

---

## 12. 项目级浏览器策略

如果某个项目频繁使用浏览器、Chrome extension、Playwright 或登录态网页，应建议新增项目级浏览器策略文件。

默认建议位置：

`<project>/docs/codex/06_BROWSER_POLICY.md`

如果项目已有特殊记忆结构，应按项目自己的命名和路由建议。

新增前必须说明为什么需要、会记录什么、什么时候读取、是否会增加维护负担，并等待确认。

## 13. 复盘触发

以下情况任务结束后应建议复盘：

- 浏览器任务失败
- 页面被 block
- 登录流程中断
- Chrome extension 使用边界不清
- Computer Use 误触窗口
- Playwright 不适合当前网站
- 发现某个网站不适合自动化
- {{USER_NAME}} 手动接管过敏感流程
- 出现新的浏览器安全经验

写入任何规则或记忆前必须先问 {{USER_NAME}}。
