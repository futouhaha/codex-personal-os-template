# 可复用 Prompt

这个文件用于保存 {{USER_NAME}} 和 Codex 跨项目可复用的 prompt、任务模板和协作模板。

这个文件不保存一次性 prompt。只有已经验证好用、未来可能复用、能降低下次沟通成本的 prompt，才适合写入这里。

写入前必须先给 {{USER_NAME}} 建议，并等待确认。

---

## 1. 什么时候读取本文件

遇到以下情况时，读取本文件：

- 需要把模糊想法改写成 Codex 可执行任务
- 需要启动一个新长期项目
- 需要做任务复盘
- 需要判断记忆应该写到哪里
- 需要浏览器安全判断
- 需要安装工具前做说明
- 需要生成 Word / PPT / Excel / HTML / Markdown 报告
- 需要飞书发布或飞书文档草稿
- 需要长任务施工卡
- 需要 bug 排查模板
- 需要项目阶段交接模板
- 需要把 OpenClaw 的经验迁移到 Codex
- 用户说“给我一段可以直接复制给 Codex 的 prompt”

不要在每个普通任务中默认读取本文件。只有当前任务需要模板化表达时再读取。

---

## 2. Prompt 质量规则

一个可复用 prompt 应该包含：

- 背景
- 目标
- 输入
- 输出
- 限制
- 操作边界
- 完成标准
- 是否允许修改文件
- 是否需要确认
- 是否需要复盘沉淀

好的 prompt 应该让 Codex 清楚知道要做什么、为什么做、用哪些资料、不要做什么、最终交付什么、怎么判断完成、哪些动作需要先问 {{USER_NAME}}。

不要保存太长太散、只适合一次任务、含有敏感信息、已经过期、没有验证过、只是在聊天里随口说过的 prompt。

## 3. Codex 任务判断 prompt

适用场景：把一个模糊想法变成 Codex 可执行任务。

```text
请先不要直接执行。

我想做的事情是：

【在这里描述想法】

请你先帮我完成任务判断和执行规划：

1. 判断这个任务属于哪类问题：一次性任务、长期项目、工具/自动化、文档生成、网页/原型开发、知识库/RAG 或其他。
2. 判断它是否适合在 Codex 里执行。如果更适合先在 ChatGPT 或普通对话里讨论，请直接告诉我原因。
3. 如果适合 Codex，请给我 2 到 3 种可能的执行路径。
4. 给出你的推荐路径，并说明原因。
5. 告诉我你还需要问我的少量关键问题。不要一次问太多，只问会明显影响方向的问题。
6. 在我确认前，不要创建文件、修改文件、安装依赖、访问外部系统或写入记忆。

输出格式：

## 初步判断
...

## 可能路径
...

## 推荐方案
...

## 需要你确认的问题
...

## 确认后我会做什么
...
```

4. 在修改文件前，先说明你准备怎么查。
5. 如果需要安装、删除、移动、重构、改配置，必须先问我。

输出：

## 初步判断
...

## 最可能原因
...

## 建议排查步骤
...

## 需要你提供的信息
...

## 如果确认后我会怎么修

## 15. Prompt 更新规则

新增、修改或删除本文件中的 prompt 前，必须先向 {{USER_NAME}} 提出建议，说明为什么需要、新 prompt 适用什么场景、是否已经验证好用、是否跨项目复用、是否更适合项目 prompt library、是否未来应该升级为 Skill、是否存在敏感信息风险。

## 16. 清理规则

当 prompt 太多、互相重复、过期、太长、不适合复用、只是一次性内容、已经升级为 Skill、应该移动到项目 prompt library、包含不该保留的信息时，应建议整理。

清理前必须先给整理方案，等待 {{USER_NAME}} 确认后再修改。
