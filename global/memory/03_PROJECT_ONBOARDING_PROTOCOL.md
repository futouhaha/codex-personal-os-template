# 项目启动协议

这个文件用于指导 Codex 在新建长期项目时，先和 {{USER_NAME}} 对齐项目目标、边界、交付物、风险、工具和记忆结构。

新项目不要直接开干。先完成 Project Onboarding，等 {{USER_NAME}} 确认后，再创建或修改项目文件。

---

## 1. 什么时候使用本协议

当 {{USER_NAME}} 准备开始以下类型任务时，使用本协议：

- 长期项目
- AI 产品原型
- 轻量小工具
- HTML / React / 前端网页系统
- AI 学习系统
- 内容生产系统
- 销售 / 客服 / 传播类 Copilot
- 知识库 / RAG 相关项目
- 飞书自动化
- 浏览器自动化
- workflow / agent / skill / plugin 体系
- 任何需要持续迭代、记录进展、沉淀经验的项目

如果只是一次性小任务，不需要完整 Project Onboarding。

---

## 2. 什么时候不使用完整流程

以下情况不需要完整 Project Onboarding：

- 只是问一个概念
- 只是轻量脑暴
- 只是临时写一段文案
- 只是生成一个一次性小文件
- 只是修一个很小、边界明确的 bug
- 只是临时跑一个命令
- 用户明确说“先别项目化”

如果不确定是否需要项目化，先判断：这个任务看起来像一次性任务，还是未来会持续迭代的项目？

不要为了显得系统化，把所有小任务都变成项目。

---

## 3. 已有项目和特殊项目优先规则

如果当前目录已经是一个项目，开始前先检查是否存在：

- 项目级 `AGENTS.md`
- 项目记忆目录
- 项目索引文件
- 特殊记忆结构
- 已有任务日志或状态文件

如果存在项目级 `AGENTS.md`，应优先读取并遵守。

如果项目已有成熟的特殊记忆结构，不要强行改成默认 `docs/codex/00–05`。默认模板只用于新项目或尚未建立记忆结构的项目。

如果现有项目规则与全局安全红线冲突，优先遵守全局安全红线，并向 {{USER_NAME}} 说明冲突点。

---

## 4. 默认流程

Project Onboarding 按 6 步进行：

1. 判断项目类型。
2. 检查是否已有项目级规则或特殊记忆结构。
3. 用少量关键问题和 {{USER_NAME}} 对齐。
4. 根据回答补充 {{USER_NAME}} 可能没有想到的技术盲点。
5. 给出 1 到 3 个可能的执行路径，并推荐当前最合适路径。
6. 提出项目级 `AGENTS.md` 和项目记忆结构草案，等待 {{USER_NAME}} 确认。

不要在 {{USER_NAME}} 确认前创建或修改项目文件。

---

## 5. 核心启动问题

不要一次性抛出过多问题。如果 {{USER_NAME}} 已经在描述中回答了某些问题，不要重复问。

### 1. 项目目标

这个项目想解决什么问题？它解决谁的什么痛点？做成后希望带来什么变化？

### 2. 最终交付物

这个项目最后希望拿到什么？可能是网页原型、HTML demo、React 小工具、文档系统、飞书自动化流程、知识库、RAG demo、Copilot workflow、报告生成器或产品雏形。

如果 {{USER_NAME}} 不确定，Codex 应给出 2 到 3 个可能交付形态，并推荐一个最小可用版本。

### 3. 使用者和场景

判断是 {{USER_NAME}} 自己用、团队内部用、客户 / 用户用、公开展示，还是学习验证。使用者不同，复杂度、权限、安全、部署和交付方式都会不同。

### 4. 当前已有素材

包括想法描述、文档、表格、PDF、PPT、图片、旧项目、参考产品、飞书文档、网页链接、数据源、代码仓库、目录结构、手写笔记等。

资料不完整时，先判断能否做最小版本，不要因为资料不全就卡住。

### 5. 项目边界

确认当前阶段先不做什么，例如后端、登录、数据库、部署、真实 API、外部发布、敏感账号、复杂权限等。

### 6. 工具和外部系统

判断是否涉及 Node / npm、HTML / CSS / JavaScript、React / Vite、Python、飞书 CLI、GitHub、Playwright、Chrome extension、Computer Use、Word / PPT / Excel、部署平台、知识库 / RAG、第三方 API 等。

如果 {{USER_NAME}} 不知道该选什么技术，先解释技术地图，再给推荐方案。

### 7. 近期完成标准

怎样算当前阶段先做成了？例如可以打开页面、生成文件、跑通流程、完成一次真实任务、被别人试用、整理出报告、保存项目进度或进入下一轮迭代。

近期目标和完成标准用于生成项目当前状态文件，不默认写入项目 `AGENTS.md`。

---

## 6. 自适应提问规则

Project Onboarding 不是死问卷。

如果项目很小，只问最关键的 3 到 4 个问题。  
如果项目复杂，可以分轮问，每轮只问当前最关键的问题，每轮之后总结当前理解。  
如果 {{USER_NAME}} 不知道怎么回答，给示例、选项、默认建议，并说明为什么重要。

---

## 7. 项目诊断输出

问答结束后，不要立刻创建文件。

先输出一份项目诊断，包含：

1. 项目类型
2. 当前阶段
3. 推荐项目路径
4. 最小可用版本建议
5. 主要风险
6. 需要确认的边界
7. 建议使用的工具
8. 是否需要项目记忆区
9. 是否需要项目级 `AGENTS.md`
10. 是否需要未来做 Skill

---

## 8. 模板使用规则

完成 Project Onboarding 问答后，如果需要生成项目级文件，应读取全局模板目录：

`{{CODEX_GLOBAL_MEMORY_DIR}}/templates/`

优先读取：

- `templates/PROJECT_AGENTS_TEMPLATE.md`
- `templates/PROJECT_MEMORY_STRUCTURE_TEMPLATE.md`

必要时读取：

- `templates/PROJECT_MEMORY_FILE_TEMPLATES.md`

模板不能直接原样复制。Codex 必须根据 Project Onboarding 的问答结果进行定制。

创建项目文件的默认分工：

- 使用 `PROJECT_AGENTS_TEMPLATE.md` 生成极简项目 `AGENTS.md`，只包含项目识别、记忆入口、记忆路由、必要特殊规则和任务结束提醒。
- 使用 `PROJECT_MEMORY_STRUCTURE_TEMPLATE.md` 判断是否需要项目记忆区、采用默认结构还是尊重特殊结构。
- 使用 `PROJECT_MEMORY_FILE_TEMPLATES.md` 生成具体项目记忆文件的初始内容。

项目 `AGENTS.md` 不负责保存每个记忆文件的详细职责。每个项目记忆文件的职责，应写在项目记忆入口文件中，通常是 `docs/codex/00_INDEX.md`。

如果项目已有成熟特殊结构，模板只能作为参考，不应覆盖现有结构。

在 {{USER_NAME}} 确认前，不要创建或修改实际项目文件。

## 9. 项目路径建议

长期 Codex 项目默认建议放在：

`{{CODEX_PROJECTS_ROOT}}/<项目名>`

不要把长期项目放在 Downloads、Desktop 或 Codex 自动生成的 projectless 临时目录。

如果项目已经存在于其他路径，先向 {{USER_NAME}} 确认是否继续使用原路径。

不要在 Codex 正在运行任务时，擅自移动或重命名项目目录。

---

## 10. 项目 AGENTS.md 建议

长期项目应提出项目级 `AGENTS.md` 草案。

项目级 `AGENTS.md` 的作用是：

- 说明这个项目是什么
- 说明项目记忆入口在哪里
- 说明任务开始时怎么读取项目记忆
- 记录必要的项目特殊规则
- 说明任务结束后怎么提出项目记忆更新建议

项目级 `AGENTS.md` 应保持极简。当前阶段、近期目标、完成标准、常用命令、工具配置、浏览器边界和项目历史，应写入项目记忆区，而不是写入项目 `AGENTS.md`。

---

## 11. 项目记忆结构建议

长期项目默认建议建立项目记忆区，常见为：

`<project>/docs/codex/`

默认结构：

```text
docs/codex/
  00_INDEX.md
  01_CURRENT_STATE.md
  02_TASK_LOG.md
  03_DECISIONS.md
  04_LEARNINGS.md
  05_TOOLING.md
```

这 6 个文件构成项目记忆的最小长期闭环。

如果项目已有特殊记忆结构，应先尊重现有结构。只有在 {{USER_NAME}} 确认需要升级或迁移时，才提出调整方案。

---

## 12. 可选扩展结构

项目后续变复杂时，可以建议新增：

```text
docs/codex/
  06_BROWSER_POLICY.md
  07_PROMPT_LIBRARY.md
  08_DATA_SOURCES.md
  09_DEPLOYMENT.md
```

新增任何项目记忆文件前，必须先向 {{USER_NAME}} 说明建议新增哪个文件、为什么现在需要、以后记录什么、什么时候读取、是否增加维护负担，并等待确认。

---

## 13. 当前状态初始化

如果 {{USER_NAME}} 确认建立项目记忆区，应初始化 `docs/codex/01_CURRENT_STATE.md`。

它用于记录当前项目目标、当前阶段、已确认交付物、当前边界、下一步建议和未确认问题。

它不是任务日志。任务日志应写入 `docs/codex/02_TASK_LOG.md`。

---

## 14. 项目记忆路由

项目 `AGENTS.md` 应写清楚如何调用项目记忆。

默认建议：

- 开始重要任务前，读 `docs/codex/00_INDEX.md` 和 `docs/codex/01_CURRENT_STATE.md`
- 涉及历史决策时，读 `docs/codex/03_DECISIONS.md`
- 涉及以前踩坑、bug、工具问题时，读 `docs/codex/04_LEARNINGS.md`
- 涉及依赖、CLI、部署、浏览器、外部工具时，读 `docs/codex/05_TOOLING.md`
- 任务结束后，先提出记忆更新建议，等 {{USER_NAME}} 确认后再写入

不要默认每次读取所有项目记忆文件。

如果项目有特殊记忆结构，按项目自己的索引和路由执行。

---

## 15. 技术盲点提醒

当发现 {{USER_NAME}} 没有提到但会影响项目的重要技术点时，Codex 应主动提醒，例如本地还是网页版本、是否需要后端、数据库、账号系统、部署、文件上传、真实 API、知识库 / RAG、隐私安全、长期维护、项目记忆或未来 Skill。

提醒时不要制造焦虑，可以建议先用轻量默认方案。

## 17. 用户想跳过 Onboarding 时

如果 {{USER_NAME}} 明确说“不需要 Project Onboarding，直接做”，可以跳过完整流程。

但仍应快速确认当前任务目标、交付物、是否允许修改文件、是否有高风险操作。

如果涉及长期项目、高风险动作、外部系统、部署、登录态网页、安装工具，不能完全跳过确认规则。

如果 Project Onboarding 流程被多次使用并稳定有效，可以考虑做成 Skill，例如 `project-onboarding`。

做成 Skill 前，需要 {{USER_NAME}} 确认。
