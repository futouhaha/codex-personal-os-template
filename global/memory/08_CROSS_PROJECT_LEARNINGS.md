# 跨项目经验

这个文件用于保存 {{USER_NAME}} 和 Codex 在多个项目中反复验证过的跨项目经验。

它不是任务日志，也不是项目进度记录。它只记录那些未来做类似项目时值得复用、提醒或避免重复踩坑的经验。

核心原则：

- 只记录跨项目有价值的经验。
- 不记录单个项目的普通进度。
- 不记录原始聊天全文。
- 不记录敏感信息。
- 写入前必须先给 {{USER_NAME}} 建议，并等待确认。
- 如果某条经验只属于当前项目，应写入该项目记忆区，不要写进这里。

---

## 1. 什么时候读取本文件

遇到以下情况时，读取本文件：

- 当前任务看起来像以前做过的同类项目
- 同类问题在多个项目中重复出现
- 需要总结“以后做类似项目应该注意什么”
- 需要判断某个经验是否已经被验证过
- 需要避免重复踩坑
- 需要做项目启动、任务复盘、工具选择、浏览器策略、文件生成、知识库、自动化等跨项目判断
- 需要从多个项目中提炼通用方法
- 任务复盘时判断是否有经验值得升级为跨项目经验

不要在每个普通任务中默认读取本文件。只有当前任务和跨项目经验有关时再读取。

---

## 2. 什么适合写在这里

适合写入本文件的内容：

- 多个项目都适用的经验
- 多个项目反复出现的卡点
- 已经验证有效的方法
- {{USER_NAME}} 的长期系统设计偏好
- 跨项目工具使用经验
- 跨项目浏览器和安全经验
- 跨项目文档生成经验
- 跨项目项目记忆经验
- 跨项目 Project Onboarding 经验
- 跨项目 Skill 候选经验
- 能帮助未来类似项目更快启动、更稳执行的提醒

典型例子：

- 长期项目默认建立 `docs/codex/00–05` 项目记忆结构。
- 新长期项目不要直接开干，先做 Project Onboarding。
- 工具安装前先判断项目内安装还是全局安装。
- 飞书、Chrome、Computer Use 等外部系统任务，默认先出方案和边界，确认后执行。
- 浏览器登录、验证码、密码、支付、私信等流程由 {{USER_NAME}} 手动接管。
- 复杂任务要先给 full picture，再拆阶段，再执行。
- 任务结束后不要只说完成，要判断是否有经验值得沉淀。

---

## 3. 什么不适合写在这里

不要写入本文件：

- 某个项目当前做到哪一步
- 某个项目的一次性任务日志
- 某个项目的具体 bug 细节
- 某个项目的临时技术选择
- 某个项目的临时文件路径
- 某个项目的短期下一步
- 原始聊天全文
- 没有复用价值的执行碎片
- 未确认的猜测
- 很快会过期的信息
- 账号、密码、验证码、token、API key、密钥、支付信息、私信、私密聊天、敏感数据

这些内容应该进入对应位置：

- 项目进度 → 项目当前状态或任务日志
- 项目决策 → 项目决策文件
- 项目踩坑 → 项目经验文件
- 项目工具配置 → 项目工具文件
- 全局硬规则 → `~/.codex/AGENTS.md`
- 复盘分类规则 → `04_MEMORY_AND_RETROSPECTIVE_POLICY.md`
- 可复用 prompt → `09_REUSABLE_PROMPTS.md`
- 稳定流程 → 未来考虑 Skill

---

## 4. 和复盘规则的关系

`04_MEMORY_AND_RETROSPECTIVE_POLICY.md` 负责判断：

- 这次任务是否值得复盘
- 哪些内容值得记
- 应该写到哪个文件
- 是否应该升级为全局规则
- 是否应该升级为跨项目经验
- 是否应该未来做成 Skill

本文件负责保存：

- 已经确认过的跨项目经验
- 多个项目都能复用的方法
- 未来类似项目应该提前注意的提醒

也就是说：

```text
04 = 怎么判断和分拣
08 = 分拣后保存的跨项目经验
```

写入本文件前，必须先经过复盘判断，并获得 {{USER_NAME}} 确认。

---

## 5. 和项目经验的关系

项目级经验优先写入当前项目经验文件。

只有当某条项目经验满足以下条件时，才建议升级到本文件：

- 在多个项目中重复出现
- 明显不只属于当前项目
- 对未来类似项目有帮助
- 已经被验证有效
- 不包含项目敏感信息
- {{USER_NAME}} 确认值得跨项目复用

升级时不要直接搬运项目原文。应先提炼成通用经验，去掉项目私有细节。

---

## 6. 经验格式

每条跨项目经验建议使用统一格式：

```md
## YYYY-MM-DD｜经验标题

### 经验类型
项目启动 / 工具安装 / 浏览器安全 / 文件生成 / 项目记忆 / 任务复盘 / Skill 候选 / 其他

### 适用场景
这条经验适合在什么情况下使用。

### 经验内容
具体经验是什么。

### 为什么重要
如果不注意，可能带来什么问题。

### 推荐做法
下次遇到类似情况时，建议怎么做。

### 不适用场景
什么时候不要套用这条经验。

### 来源
来自哪个项目或哪类任务的复盘。不要记录敏感细节。

### 是否可能升级
是否未来可能升级为 `AGENTS.md`、全局记忆文件、Skill 或项目模板。
```

如果经验很短，可以简化，但至少要包含适用场景、经验内容和推荐做法。

## 7. 经验分类

本文件中的经验可以按以下类别组织：

- Project startup learnings：项目启动相关经验。
- Memory system learnings：记忆系统相关经验。
- Tooling learnings：工具和环境相关经验。
- Browser and security learnings：浏览器和安全相关经验。
- Product and system design learnings：产品和系统设计相关经验。
- Document and output learnings：文档、报告、Word、PPT、Excel、Markdown、HTML 输出经验。
- Workflow and Skill learnings：流程和 Skill 相关经验。

## 8. 初始设计基线

以下内容来自 Codex Personal OS 初始设计。它们不是“多个真实项目已经验证过的经验”，而是当前系统的初始设计基线。后续应通过项目复盘继续验证、修正或删除。

### 长期项目默认建立 `docs/codex/00–05`

适用场景：一个 Codex 项目会持续迭代、产生多次任务、需要记录进展、决策、工具和经验。

经验内容：长期项目默认 propose 以下结构：

```text
docs/codex/
  00_INDEX.md
  01_CURRENT_STATE.md
  02_TASK_LOG.md
  03_DECISIONS.md
  04_LEARNINGS.md
  05_TOOLING.md
```

推荐做法：长期项目默认 propose `00–05`。复杂能力按需增加 `06–09`，新增前必须说明原因并等待 {{USER_NAME}} 确认。

不适用场景：一次性任务、临时草稿、小修小补。

### 详细流程不塞进全局 AGENTS.md

适用场景：设计全局 `AGENTS.md`、全局记忆文件夹、项目 `AGENTS.md`、项目记忆结构时。

经验内容：全局 `AGENTS.md` 应采用“短规则 + 调用表”结构。它只保存必须每次知道的红线、默认行为和路由规则。详细协议、判断方法和模板应放入全局记忆文件夹，按任务场景读取。

推荐做法：红线规则放 `AGENTS.md`，详细流程放全局记忆文件，通过调用表连接两者。

### Codex 应先作为顾问，再作为执行者

适用场景：所有需要 Codex 执行、规划、修改文件、安装工具、设计项目结构的任务。

经验内容：{{USER_NAME}} 希望 Codex 默认是“顾问 + 执行搭档”，不是上来就执行的工具。

推荐做法：遇到模糊需求，先初步判断，再问少量关键问题。遇到高风险操作，必须先说明风险并等待确认。

### 项目经验不等于全局经验

适用场景：任务复盘、项目记忆整理、跨项目经验升级时。

经验内容：项目经验应先写入项目记忆。只有当经验跨项目复用、重复出现、并且 {{USER_NAME}} 确认后，才升级到本文件。

推荐做法：先项目内沉淀，再判断是否升级全局。升级时提炼成通用经验，去掉项目私有细节。

### 浏览器和外部系统优先走低权限路径

适用场景：任务涉及 Web Search、In-app Browser、Chrome extension、Computer Use、Playwright、飞书、小红书、Gmail、Notion、登录态网页时。

经验内容：浏览器和外部系统任务应优先使用低权限路径。

```text
Web Search
→ CLI / API
→ In-app Browser
→ Chrome extension
→ Computer Use
→ Playwright 用于项目内可重复测试
```

推荐做法：能查公开资料就用 Web Search；能用 CLI / API 就不要手动操作网页；必须登录态时先问 {{USER_NAME}}；遇到敏感流程必须停止并让 {{USER_NAME}} 接管。

## 9. 升级候选

当本文件中的某条经验反复被验证，可以考虑升级。

### 升级到 `~/.codex/AGENTS.md`

适合变成必须每次遵守的红线、不遵守可能带来风险、影响所有项目、{{USER_NAME}} 明确确认的经验。

### 升级到协议文件

适合已经变成稳定流程、需要更详细步骤、会影响多个项目的经验。

可能升级到 `02_TASK_ROUTING.md`、`03_PROJECT_ONBOARDING_PROTOCOL.md`、`04_MEMORY_AND_RETROSPECTIVE_POLICY.md`、`05_BROWSER_AND_SECURITY_POLICY.md`、`06_TOOLING_AND_INSTALL_POLICY.md`、`07_SKILL_STRATEGY.md`。

### 升级到 Skill

适合重复出现 3 次以上、步骤稳定、输入输出清楚、会跨项目复用、普通 prompt 已显得重复的流程。

创建 Skill 前，先读取 `07_SKILL_STRATEGY.md`。

---

## 10. 清理规则

当经验重复、过期、太具体、已经升级为 `AGENTS.md`/协议文件/Skill、数量太多需要分类重排、经验之间存在冲突时，应建议清理。

清理前必须先给 {{USER_NAME}} 整理方案，等待确认后再修改。

---

## 11. 更新规则

更新本文件前，必须先向 {{USER_NAME}} 提出建议，说明建议新增、修改或删除哪条经验、来自哪个项目或哪类任务、为什么有跨项目价值、是否已经被验证、是否存在过度泛化风险、是否更适合留在项目记忆，以及是否应该升级。
